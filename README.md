# Project Technical Summary

## 1. High-Level Vision & Current State

- Altius is a single-user discipline economy. The person names one main goal (the anchor), logs work in plain language, and earns a point balance they can spend on rewards. Work adds points. Leisure takes them back. There is no account, social graph, or cloud sync. The product is a finished client app at release `v1.0.41-prod` (`src/release.ts`), phone-first and also usable in a desktop browser.
- Target platform is a portrait standalone PWA (`display: standalone`, `orientation: portrait`, theme `#F4F4F5`) aimed at a phone-width column (`max-w-[430px]`). It ships as a static site. A sideload Android package is not part of this repo’s build.
- Stack: React 19 and TypeScript, Vite 8, Tailwind CSS v4 via `@tailwindcss/vite`. Vitest 5 runs in Node before `tsc -b` and `vite build` (`npm run build`). Lint is Oxlint. Icons are local SVG components in `src/components/Icons.tsx`. `lucide-react` is listed in devDependencies and is not imported. UI font is Plus Jakarta Sans; numbers use Space Grotesk, both loaded from Google Fonts in `index.html`. Production is a static Vite build on Vercel. There is no `vercel.json` and no server runtime in the repo.

## 2. Architecture & File Structure

- `src/types/pulse.ts` is the only shared model. `src/types/index.ts` re-exports it. `src/services/` holds scoring, audit, persistence, demo data, and the intro gate. `src/services/engine/` is the pure economy. `src/services/economy.ts` re-exports that engine for UI callers. `src/hooks/` owns React state. `src/components/` is presentation. `src/lib/` holds Gemini, dates, greeting, audio, confetti, and the history back stack. `src/App.tsx` is the only screen.
- There is no router and no server. `PulseProvider` loads state once, and `commit` writes the whole `PulseState` through `saveState`. Screens read slices: economy, ledger, vault, settings, sensory, notice. Overlays are local React state (`feed` | `vault`, plus one modal). The browser back stack in `src/lib/backStack.ts` pushes a history entry per open sheet, vault tab, and intro step so an Android edge swipe closes the top layer. The welcome name sheet is not on that stack.
- The only third-party API is Gemini, called from the browser in `src/lib/gemini.ts`. `callGemini` posts to `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` with an 8 second timeout. It tries `gemini-3.8-flash`, then `gemini-3.5-flash-lite`, then `gemini-3-flash-preview`. The key is optional in the request: a stored key is sent as `x-goog-api-key` and a query param; an empty key still hits the endpoint and failure falls through. No other backend, database, or auth provider exists.

## 3. Data Models & State Management

- `PulseState` holds the balance, anchor, theme, transactions, vault, habit decks, `chainStreak`, `forgeStreak`, and an economy dial (`lenient` | `balanced` | `hardcore`). The forge baseline is 120. The live target is the median judged points of the last 7 active days, clamped to 80–180. Grace is half of that target. The unnamed anchor is `Your main goal`.
- A `Transaction` is `EARN` or `SPEND` with `id`, `title`, `points`, `timestamp`, `date`, optional `reasoning`, `formula_breakdown`, `effort_strain`, `anchor_alignment`, `multiplier`, and `weight_class`. Spends may use a vault category or `Decay Audit`. A `VaultItem` stores `category`, `measurementType` (`time` | `money`), `durationMinutes` or `priceDollars`, and `baseCost`. Old Gaming, Items, Dining, and Events rows migrate on load. Weight classes are Heavyweight `2.0x`, Cruiserweight `1.5x`, Middleweight `1.0x`, and Lightweight `0.5x`.
- Persistence is `localStorage` only, one key per field, via `src/services/persistence.ts`. Keys: `pulse_balance`, `pulse_txs`, `pulse_vault`, `pulse_anchor`, `pulse_sound`, `pulse_last_audit`, `pulse_gemini_key`, `pulse_theme`, `pulse_profile`, `pulse_demo`, `pulse_demo_snapshot`, `pulse_intro`, `pulse_streak_count`, `pulse_streak_state`, `pulse_username`, `pulse_onboarded`. `pulse_streak_closed` records the last closed day. `pulse_decay` is removed on save. `navigator.storage.persist()` is requested at startup and its result is only logged.
- `pulse_profile` is stamped `fresh-1` when missing. A different tag no longer wipes a ledger that is already stored; the tag is migrated and the rows are kept. An empty store still starts from `freshState()`. Transactions and vault rows are parsed defensively; a totally invalid array becomes empty, and mixed arrays drop the bad rows. `is_locked` round-trips when present. `saveState` writes on every `commit`. There is no cross-device sync.
- Backup export is `{ app: 'Altius', version: '1.4.0', exported_at, storage }` and downloads `altius-backup.json`. Restore replaces app keys, and rolls back if parsing fails. A file without a `storage` envelope is merged by `mergeBackup` (balance, anchor, transactions, vault, sound, username, onboarded only). Demo mode snapshots the real profile in `pulse_demo_snapshot` and restores it on exit. Three version labels coexist: npm `0.0.0`, release `v1.0.41-prod`, backup schema `1.4.0`.

## 4. Key Features & Workflows Implemented

- Name gate, then a skippable 7-step intro for an empty, unnamed, unseen profile. Header question mark reopens the guide. Greeting uses the local hour (`morning` 5–11, `afternoon` 12–16, otherwise `evening`) and a lowercased username. Light/dark theme, Web Audio sounds, and vibration patterns.
- Log and judge: duration is clamped to 5–360 minutes. A named anchor is required. Gemini (`gemini-3.8-flash`, temperature 0.1) returns only `relevance` (DIRECT, ENABLING, GENERAL), `strain` (HIGH 60, MEDIUM 40, LOW 20), and `weightClass` (HEAVYWEIGHT 2, CRUISERWEIGHT 1.5, LIGHTWEIGHT 1). Points are `round(strain × relevance × weight)` in `src/services/engine/judging.ts`. An empty key never calls the network. Three habit decks of 3–5 habits sit on the feed. They run in order, share a 60–85 point pool scored once on save, and a heavyweight log clears one pacing warning. Cutoffs default to 13:00 and 19:00, change on a 48-hour cooldown, and start the next day. Three warnings at the nightly close collapse both streaks and charge 20 points per unfinished habit. Seven clean days bank one PTO token. Judged logs are not multiplied by a streak. Habit bounties are flat. New ids come from `crypto.randomUUID()`.
- Daily loop: today’s earned points are the sum of `EARN` rows whose `date` is the local calendar day (`YYYY-MM-DD` via `toLocaleDateString('en-CA')`). Stored `timestamp` values for new rows are ISO-8601. The feed formats those for display. The split capsule shows forge points against the live target, with a notch at half, and three deck pips for the chain. On load, `runDecayAudit` closes every local day from `lastAuditDate` up to, but not including, today. Earned at or above the forge target increments `forgeStreak`. The grace band holds it. Under the grace floor it resets to 0, records a locked `Decay Audit` spend, and collects 15 points, or 20 at tier 2 or higher, without taking the balance below 0. Any uncollected fee is written on that row. `pulse_last_audit` moves to today only after the walk finishes. Settings copy explains these rules.
- Spend now, or park a bounty. Time costs `round((minutes / 60) × timeMultiplier)`. Money costs `round(dollars × cashMultiplier)`. Balanced is 120 points an hour and 20 points a dollar. The weaker of the chain and forge streaks discounts the charge by 10, 15, or 20 percent from tier 1. Immediate spend and vault unlock both refuse a cost the balance cannot cover. Saving or editing a bounty does not charge points. Unlock writes a spend and leaves the bounty in the vault. Deleting a ledger row reverses its points, floors the balance at 0, and says when part of an earn could not be recovered. Decay rows are locked and cannot be deleted or refunded. Feed filters: All, Heavy+ (`EARN` and multiplier `>= 1.5`), Aligned (`EARN` and alignment `>= 4`), Spends. Adding or deleting a row does not recompute the forge streak from history. The nightly audit owns both streaks.
- Settings: Gemini key save and a live ping, display name, JSON export/import, demo mode with a fixed sample ledger, and Start fresh (clears balance, ledger, vault, and intro, keeps name and demo flag). Confetti plays on earn, spend, and unlock.

## 5. Active Limitations, Edge Cases & Gaps

- A closed day under 60 collects at most the current balance. The decay row still records a 15 point fee and states how many points stayed uncollected. The balance does not go negative. Deleting an earn that was already spent does the same: the balance stops at 0 and the toast names the unrecovered points.
- `currentStreak` in `src/services/engine/momentum.ts` is a different rule (consecutive days at or above 120, and any earn today counts as 1) and is only used by tests. The stored streaks are `forgeStreak` and `chainStreak`. `lifetimeStats` is unused by the UI.
- The model’s `category` is discarded, so earns have no category unless something else sets it. The concrete-proof check is an English keyword list plus “contains a digit.” Vague-but-real work and non-English logs stay at half credit. Demo rows use the same alignment bands.
- The Gemini key sits in `localStorage` in plaintext and is sent from the browser when present. A failed call still falls back to half credit and shows the error in a toast. There is no rate limit, queue, or offline outbox.
- Unlock does not remove or decrement the bounty, so the same reward can be bought repeatedly. Older rows saved before this change may still have display-string timestamps; the feed shows those strings as stored. Invalid ledger rows are dropped without notice. Tests cover the engine, demo, intro, greeting, and backup round-trip (`src/services/__tests__/`). There are no component or browser tests. Fonts require the Google Fonts network. The service worker (`vite-plugin-pwa`, `registerType: autoUpdate`) caches the shell; a stale client is possible until the worker updates.
