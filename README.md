# Project Technical Summary

This file is the design and reference brief. Paste it into Gemini. Screens, names, categories, and point formulas that are not written here are not part of the product.

## 1. High-Level Vision & Current State

- Altius is a single-user discipline economy. The person names one main goal (the anchor), logs work in plain language, and earns a point balance they can spend on rewards. Work adds points. Leisure takes them back. There is no account, social graph, or cloud sync. The product is a finished client app at release `v1.0.69-prod` (`src/release.ts`), phone-first and also usable in a desktop browser.
- The column is `max-w-[430px]`, portrait PWA (`display: standalone`, `orientation: portrait`). Light canvas is `#F4F4F5`. Dark canvas is `#09090B`. It ships as a static site. A sideload Android package is not part of this repo’s build.
- Stack: React 19 and TypeScript, Vite 8, Tailwind CSS v4 via `@tailwindcss/vite`. The feed cat is a local PNG on the balance card. Vitest 5 runs in Node before `tsc -b` and `vite build` (`npm run build`). Lint is Oxlint. Icons are local SVG components in `src/components/Icons.tsx`. `lucide-react` is listed in devDependencies and is not imported. UI font is Plus Jakarta Sans. Numbers use Space Grotesk, tabular. Both load from Google Fonts in `index.html`. Production is a static Vite build on Vercel. There is no `vercel.json` and no server runtime in the repo.
- Design contract: zinc surfaces, tactile cards, no extra UI kit, no emoji status marks. The dock is Feed, Foundation, a centered plus, Stats, Vault. Product names are Output and Foundation. Stored fields stay `forgeStreak` and `chainStreak`. Vault categories are only Gaming, Food/Drink, Items, and Events. The discipline dial locks after one free change.

## 2. Architecture & File Structure

- `src/types/pulse.ts` is the only shared model. `src/types/index.ts` re-exports it. `src/services/` holds scoring, audit, persistence, demo data, and the intro gate. `src/services/engine/` is the pure economy. `src/services/economy.ts` re-exports that engine for UI callers. `src/hooks/` owns React state. `src/components/` is presentation. Shared shells live in `src/components/Common/primitives.tsx`: `Surface` (page card), `Well` (inset), `Panel` (list card), `Eyebrow` (metric label), and `IconTile`. Metric labels use the `.eyebrow` class. Buttons share `.press` and `.focus-ring`. `src/lib/` holds Gemini, dates, greeting, audio, confetti, and the history back stack. `src/App.tsx` is the only screen.
- There is no router and no server. `PulseProvider` loads state once, and `commit` writes the whole `PulseState` through `saveState`. Screens read slices: economy, ledger, vault, settings, sensory, notice. Overlays are local React state (`feed` | `foundation` | `stats` | `vault`, plus one modal). The browser back stack in `src/lib/backStack.ts` pushes a history entry per open sheet, non-feed tab, and intro step so an Android edge swipe closes the top layer. The welcome name sheet is not on that stack.
- The only third-party API is Gemini, called from the browser in `src/lib/gemini.ts`. `callGemini` posts to `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` with an 8 second timeout. It tries `gemini-3.8-flash`, then `gemini-3.5-flash-lite`, then `gemini-3-flash-preview`. The key is optional in the request: a stored key is sent as `x-goog-api-key` and a query param; an empty key still hits the endpoint and failure falls through. No other backend, database, or auth provider exists.

## 3. Data Models & State Management

- `PulseState` holds the balance, anchor, theme, transactions, vault, habit decks, `chainStreak`, `forgeStreak`, `joinedAt`, and an economy dial (`lenient` | `balanced` | `hardcore`). `difficultyLocked` starts false. The first change to a different dial sets it, and later changes are refused until Start fresh. The output baseline is 120. The live target is the median judged points of the last 7 active days, clamped to 80–180. Grace is half of that target. The unnamed anchor is `Your main goal`. Output is the earned-points streak (`forgeStreak`). Foundation is the deck streak (`chainStreak`). Privileges use `min(chainStreak, forgeStreak)`. `streakCount` is a mirror of `forgeStreak` so an older `pulse_streak_count` save can restore Output. It is not a third streak. `StreakState` is the day status: `STALLED`, `SAFE`, or `SECURED`.
- A `Transaction` is `EARN` or `SPEND` with `id`, `title`, `points`, `timestamp`, `date`, optional `reasoning`, `formula_breakdown`, `effort_strain`, `anchor_alignment`, `multiplier`, and `weight_class`. Spends may use a vault category or `Decay Audit`. A `VaultItem` stores `category` (`gaming` | `food` | `items` | `events`), `measurementType` (`time` | `money`), `durationMinutes` or `priceDollars`, and `baseCost`. Gaming is time. Food/Drink, Items, and Events are money. There is no flat price. Older gaming, streaming, and social rows become gaming. Dining becomes food. Gear and custom become items. Outings become events. Display-string Gaming, Items, Dining, and Events rows still migrate on load. Weight classes are Heavyweight `2.0x`, Cruiserweight `1.5x`, Middleweight `1.0x`, and Lightweight `0.5x`.
- Persistence is `localStorage` only, one key per field, via `src/services/persistence.ts`. Keys: `pulse_balance`, `pulse_txs`, `pulse_vault`, `pulse_anchor`, `pulse_sound`, `pulse_last_audit`, `pulse_gemini_key`, `pulse_theme`, `pulse_profile`, `pulse_demo`, `pulse_demo_snapshot`, `pulse_intro`, `pulse_streak_count`, `pulse_streak_state`, `pulse_username`, `pulse_onboarded`, `pulse_discipline`. `pulse_discipline` holds decks, the habit day, `joinedAt`, pacing, warnings, PTO, both streaks, the economy dial, and habit-score flags. `pulse_streak_closed` records the last closed day. `pulse_decay` is removed on save. `navigator.storage.persist()` is requested at startup and its result is only logged.
- `pulse_profile` is stamped `fresh-1` when missing. A different tag no longer wipes a ledger that is already stored; the tag is migrated and the rows are kept. An empty store still starts from `freshState()`. Transactions and vault rows are parsed defensively; a totally invalid array becomes empty, and mixed arrays drop the bad rows. `is_locked` round-trips when present. `saveState` writes on every `commit`. There is no cross-device sync.
- Backup export is `{ app: 'Altius', version: '1.4.0', exported_at, storage }` and downloads `altius-backup.json`. Restore replaces app keys, and rolls back if parsing fails. A file without a `storage` envelope is merged by `mergeBackup` (balance, anchor, transactions, vault, sound, username, onboarded only). Demo mode snapshots the real profile in `pulse_demo_snapshot` and restores it on exit. Three version labels coexist: npm `0.0.0`, release `v1.0.69-prod`, backup schema `1.4.0`.

## 4. Key Features & Workflows Implemented

- Name gate, then a 7-step intro for an empty, unnamed, unseen profile. Steps: points for the work, the balance card, the day card, Foundation, the dock plus, Spend and Add, then name the anchor. Earlier steps can be skipped. The last step spotlights the balance card. Set anchor saves that goal and closes the guide. An empty field or `Your main goal` does not finish it. During a spotlight the matching tab is shown behind it. Header question mark reopens the guide. Greeting uses the local hour (`morning` 5–11, `afternoon` 12–16, otherwise `evening`) and a lowercased username. Light and dark theme, and sound mute, live in Settings. Web Audio sounds and vibration patterns follow that sound setting.
- Log and judge: duration is clamped to 5–360 minutes. A named anchor is required. Gemini (`gemini-3.8-flash`, temperature 0.1) returns only `relevance` (DIRECT, ENABLING, GENERAL), `strain` (HIGH 60, MEDIUM 40, LOW 20), and `weightClass` (HEAVYWEIGHT 2, CRUISERWEIGHT 1.5, LIGHTWEIGHT 1). Points are `round(strain × relevance × weight)` in `src/services/engine/judging.ts`. An empty key never calls the network. Three habit decks of 3–5 habits sit on the Foundation tab. Default names are Morning, Midday, and Evening. Each deck has a time-of-day mark, a progress tick per habit, and an Open, Locked, or Clear pill. Habit rows show an index and a point chip. The next habit is the filled row. Names, habits, and cutoff times are edited there. Judge habits scores every card and writes that point value on its row. Each cutoff opens a themed time slider and is queued with the existing button. Use PTO asks for a confirm before it spends a token. Decks run in order and share a 60–85 point pool. A heavyweight log clears one pacing warning. Cutoffs default to 13:00 and 19:00, change on a 48-hour cooldown, and start the next day. On the day a profile starts, a cutoff that is already past does not open a warning, including the late foundation check. A cutoff still ahead that day still does. Three warnings at the nightly close collapse both streaks and charge 20 points per unfinished habit. Seven clean days bank one PTO token. Judged logs are not multiplied by a streak. Habit bounties are flat. New ids come from `crypto.randomUUID()`.
- Daily loop: today’s earned points are the sum of `EARN` rows whose `date` is the local calendar day (`YYYY-MM-DD` via `toLocaleDateString('en-CA')`). Stored `timestamp` values for new rows are ISO-8601. The feed formats those for display. The day card is one pill: output grows left from the center by earned points over the live target, and foundation grows right from the center by decks finished out of 3. Under the bar, the privilege streak is the weaker of the two day counts, next to the tier discount. Weekday marks are slim bars in the same columns as their letters. An open warning freezes that discount at 0%. On load, `runDecayAudit` closes every local day from `lastAuditDate` up to, but not including, today. Earned at or above the output target increments `forgeStreak`. The grace band holds it. Under the grace floor it resets to 0, records a locked `Decay Audit` spend, and collects 15 points, or 20 at tier 2 or higher, without taking the balance below 0. Any uncollected fee is written on that row. `pulse_last_audit` moves to today only after the walk finishes. Settings copy explains these rules.
- Spend now, or park a bounty. Time costs `round((minutes / 60) × timeMultiplier)`. Money costs `round(dollars × cashMultiplier)`. Lenient is 80 points an hour and 12 points a dollar. Balanced is 120 and 20. Hardcore is 160 and 30. The weaker of the Foundation and Output streaks discounts the charge by 10, 15, or 20 percent from tier 1. An open warning freezes that discount at 0%. Category chips: Gaming violet and time, Food/Drink amber and money, Items sky and money, Events emerald and money. Food/Drink’s icon is a fork. Immediate spend and vault unlock both refuse a cost the balance cannot cover. Saving or editing a bounty does not charge points. Unlock writes a spend and leaves the bounty in the vault. Deleting a history row reverses its points, floors the balance at 0, and says when part of an earn could not be recovered. Decay rows are locked and cannot be deleted or refunded. The feed section is labeled History. Filters: All, Earned, Spent, and Decay. Spend rows show their bounty category. Adding or deleting a row does not recompute the output streak from history. The nightly audit owns both streaks.
- Stats is its own dock tab, opposite Foundation, so the plus sits in the center. It charts earned points for the last 14 local days against each day’s output target. The day letter sits in the same column as its bar. The cards under the chart are lifetime earned, lifetime spent, days on target, and the best day in the window. Those figures come from `progressWindow`, `lifetimeStats`, `earnedOn`, and `forgeTarget`. Stats does not repeat the live balance or the Output and Foundation day counts.
- Settings: light or dark appearance, sound mute, Gemini key save and a live ping, display name, JSON export/import, demo mode with a fixed sample ledger, and Start fresh (clears balance, history, vault, the dial lock, and intro, keeps name and demo flag). The discipline dial selects a level, then Confirm applies it. Confetti plays on earn, spend, and unlock.

## 5. Active Limitations, Edge Cases & Gaps

- A closed day under the grace floor collects at most the current balance. The decay row still records the 15 or 20 point fee and states how many points stayed uncollected. The balance does not go negative. Deleting an earn that was already spent does the same: the balance stops at 0 and the toast names the unrecovered points.
- `currentStreak` in `src/services/engine/momentum.ts` is a different rule (consecutive days at or above 120, and any earn today counts as 1) and is only used by tests. The stored streaks are `forgeStreak` and `chainStreak`. `streakCount` is written as a copy of `forgeStreak`.
- The model’s `category` is discarded, so earns have no category unless something else sets it. The concrete-proof check is an English keyword list plus “contains a digit.” Vague-but-real work and non-English logs stay at half credit. Demo rows use the same alignment bands.
- The Gemini key sits in `localStorage` in plaintext and is sent from the browser when present. A failed call still falls back to half credit and shows the error in a toast. There is no rate limit, queue, or offline outbox.
- Unlock does not remove or decrement the bounty, so the same reward can be bought repeatedly. Older rows saved before this change may still have display-string timestamps; the feed shows those strings as stored. Invalid ledger rows are dropped without notice. A finished habit row uses a check icon. Tests cover the engine, demo, intro, greeting, and backup round-trip (`src/services/__tests__/`). There are no component or browser tests. Fonts require the Google Fonts network. The service worker (`vite-plugin-pwa`, `registerType: autoUpdate`) caches the shell; a stale client is possible until the worker updates.
